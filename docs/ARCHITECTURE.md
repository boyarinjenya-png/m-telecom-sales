# Архитектура M-TELECOM SALES

## Компоненты

- **Android** — Kotlin, Jetpack Compose, Retrofit, Room (очередь), WorkManager, EncryptedSharedPreferences.
- **Backend** — PHP 8.2+, собственный маршрутизатор, PDO prepared statements, без обязательного Composer.
- **Admin** — HTML/CSS/JS, те же REST-методы, Leaflet + OpenStreetMap.
- **БД** — MySQL в production, SQLite в автотестах. Миграции в `backend/src/Core/Migrator.php`.

## Принципы

1. Единая серверная база для пяти менеджеров и руководителя.
2. Авторизация: `password_hash` / `password_verify`, непрозрачные токены (SHA-256 в БД).
3. RBAC на сервере.
4. История взаимодействий append-only; исправление — отдельная запись `amendment`.
5. Источник данных всегда явный: система или менеджер.
6. Карта без платного SDK.
7. WhatsApp Business Platform заложен флагом настройки, текущая фиксация — ручная.

## Карточка клиента

Центр системы. Timeline объединяет звонки, WhatsApp, встречи, КП, смены статусов, задачи и исправления в хронологическом порядке. У каждой записи есть ID, серверное время и автор.

## Классификация звонков

| Длительность подтверждённого разговора | Категория |
|---|---|
| 0–20 сек или нет соединения | Попытка дозвона |
| 21–59 сек | Короткий разговор |
| 1–5 мин | Переговоры |
| 5–10 мин | Развёрнутые переговоры |
| более 10 мин | Длительные переговоры |

Длительность ≠ заинтересованность. Интерес хранится отдельным полем.

## Синхронизация

Клиентские UUID и `idempotency_key` предотвращают дубли при повторной отправке. При устаревшем `base_updated_at` сервер возвращает конфликт и сохраняет его в `sync_conflicts` вместо молчаливой перезаписи.
